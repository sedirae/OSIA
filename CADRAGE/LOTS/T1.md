## EXEC-01 — Moteur autonome, interfaces séparées

Le moteur Linux est indépendant du frontend web et du futur client natif. La logique métier, les politiques et les données font autorité côté moteur. Points d'entrée CLI, API, service et appels internes selon T3.3. Le backend reste exploitable sans interface graphique.

## EXEC-02 — Installation Desktop ou Server

Le choix d'installation détermine l'activation des paramètres et modules internes nécessaires. Desktop vise l'usage sur un poste ; Server l'exécution en service. Il ne s'agit pas de deux moteurs métier distincts. Les cycles de démarrage, arrêt, changement de mode et reprise seront spécifiés en conception avec les droits et migrations nécessaires.

Le mode Desktop ne signifie pas qu'un client natif est déjà livré. Le mode Server n'active pas implicitement une exposition distante.

## EXEC-03 — Distribution unifiée, frontend web facultatif

Un paquet/dispositif de distribution applicative commun regroupe le moteur et les composants ; l'installation du frontend web est facultative. Le choix de mode pilote les modules activés, y compris ceux nécessaires au service web. Installer sans frontend conserve l'accès au moteur et à son API lorsqu'elle est activée pour l'usage prévu.

L'interface web est la première interface graphique ; le client GNOME est différé. Le format exact des paquets, les distributions supportées et l'installation de PostgreSQL restent à concevoir. Les mécanismes natifs Linux sont retenus ; Docker/Podman ne sont pas obligatoires (T5.2).

## EXEC-04 — REST et événements SSE

L'API REST porte commandes et lectures ; SSE diffuse le suivi événementiel. Ces contrats sont typés et versionnés. L'état persistant reste la référence après perte de connexion ; le flux d'événements n'est pas l'unique registre. L'absence de frontend web ne supprime pas l'API en usage serveur.

## EXEC-05 — Exposition et sécurité selon le mode

Liaison locale par défaut, sans exposition distante implicite. L'accès distant est activé explicitement. T5.7 exige authentification, sessions et autorisations en mode Server, et HTTPS pour les accès distants. Les protections s'appliquent aussi à une API sans frontend. Les mécanismes d'identité, d'authentification et de session précis restent à concevoir ; aucune gestion collaborative complète de comptes n'est imposée.

## EXEC-06 — Mises à jour manuelles avec notification

Les mises à jour applicatives sont manuelles avec notification, conformément au rappel T1 de T3. Les schémas évoluent par migrations contrôlées et avec conservation du dernier état cohérent. La maintenance de connecteurs B7 est un mécanisme distinct : elle ne permet pas de déployer automatiquement du code sensible ou de contourner cette politique.

## EXEC-07 — Client GNOME ultérieur

Un client natif Linux GNOME en Rust, GTK4 et libadwaita est prévu ultérieurement, distinct du moteur Python et du frontend web. Il utilise les interfaces du moteur. Il ne constitue pas un livrable V1 ni une obligation d'introduire Rust dans le moteur initial.
